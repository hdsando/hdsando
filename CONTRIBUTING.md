# Contributing

Contributions should make the public work easier to inspect, reproduce or validate.

## Report a problem

[Open an issue](https://github.com/hdsando/hdsando/issues) and include:

- The source revision and module concerned.
- Your Excel version, operating system and relevant configuration.
- Minimal reproduction steps with synthetic input.
- Expected behaviour, actual behaviour and any error message.

Remove identifying information from screenshots and logs.

## Propose a change

Explain the problem and the intended behaviour before a substantial change. Keep each pull request focused.

For a code change, describe how it was checked and include a small example with independently defined expected results. State clearly when execution in Excel has not been tested.

For an analytical rule, explain the assumptions, threshold choice and known limitations. Include both a case that should trigger the rule and one that should not.

For a documentation change, ensure that paths exist and that instructions describe the repository as it currently stands.

## Data and evidence

Use synthetic data in public issues and pull requests. Performance claims should include the environment, input size, procedure, repetitions and measured results.

Describe security concerns without publishing credentials or confidential records. If GitHub private vulnerability reporting is enabled, use that channel for a sensitive report.
